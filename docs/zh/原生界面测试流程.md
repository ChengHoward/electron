# 原生界面测试流程

局部修改默认按影响范围验收。只有公共接口、生命周期、输入行为或多个模块共用实现发生变化时，才增加对应回归或完整预览。

## 按修改范围运行

`run_native_ui_checks.py` 提供 `focus`、`menu`、`textarea`、`scrollbars`、`material`、`page-info` 和 `all` 范围。默认运行 `focus`；完整预览必须显式指定 `--scope all`。原 `run_native_ui_preview.py` 保留兼容入口。

例如，焦点框的圆角或裁剪修复只需一次编译，再检查浅深主题、鼠标和键盘导航，以及实际截图：

```powershell
python test/native-panels/run_native_ui_checks.py `
  --electron ../out/Release/electron.exe `
  --output ../out/native-ui-focus `
  --scope focus
```

这个范围运行三项焦点检查，覆盖整行操作、图标按钮和实际 PageInfo。输入框改动选择 `textarea`，滚动条改动选择 `scrollbars`，菜单改动选择 `menu`。需要确认范围时，追加 `--dry-run` 只显示命令，不启动界面。

公共行为变更需要完整预览时，显式运行：

```powershell
python test/native-panels/run_native_ui_checks.py `
  --electron ../out/Release/electron.exe `
  --output ../out/native-ui-full `
  --scope all
```

公开参数或类型改变时补 schema 和类型检查；未修改的模块不反复运行。仅修改文档不重新编译 Electron。

## 失败后只补对应单项

从 `results.json` 复制失败用例的完整名称，用 `--case` 精确选择，并写入新的结果目录：

```powershell
python test/native-panels/run_native_ui_checks.py `
  --electron ../out/Release/electron.exe `
  --output ../out/native-ui-rerun `
  --case 'focus ring: PageInfo security row paints a complete mouse and Tab outline before native navigation'
```

先区分产品失败、窗口遮挡、输入驱动和异步绘制时序。保留原始失败报告；补测仍使用真实键鼠、窗口归属检查和原断言。需要汇总结果时，逐项注明原报告、补测报告及其摘要，不修改原始失败记录。

## 打包与发布验收

1. 编译一次，记录实际可执行文件的 SHA-256；之后的报告绑定这个产物。
2. 运行受影响范围并检查截图。只有实现改变或出现新的相关问题，才补跑对应检查。
3. 直接打包已验收的产物；没有重新编译时不重跑构建验收。
4. 从实际本地镜像全新安装一次，核对包、可执行文件、资源、公开类型和受影响模块。暂存镜像不再重复安装相同内容。
5. 发布 GitHub 后核对附件摘要和实际下载内容，不再重复运行同一二进制的完整界面测试。

原版与修订版的对照只需保留一组有效证据；未改变相关测试逻辑和二进制时，不因其他测试驱动调整而重复对照。重新编译得到不同产物后，重新验证受影响范围。

同版本覆盖发布时同时更新 ZIP、npm 包、嵌入校验和、镜像元数据和文档。安装验证使用独立缓存，避免命中旧版本内容；旧发布和旧失败证据单独保留。
