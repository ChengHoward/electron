## 2026-09-11：loadURLWithResponse（per-WC 主文档假响应）

### 背景

需要「导航到真实 URL、主文档返回指定正文」，且不影响同 Session 其它 WebContents。Session 级 `protocol.handle` 会误伤并发窗口。

### 修改

1. `NavigationResponseOverrideRegistry`：按 `WebContents*` 登记一次性 override（URL 忽略 fragment）
2. `ProxyingURLLoaderFactory::CreateLoaderAndStart`：主文档命中则 `SendContents`，优先于 `protocol.handle`
3. `WebContents::LoadURLWithResponse` + JS `loadURLWithResponse`（不接受 loadURL options）
4. 失败 / 提交 / 销毁时清理 pending

### 用法

```js
await wc.loadURLWithResponse('https://example.com/', {
  headers: { 'content-type': 'text/html; charset=utf-8' },
  body: '<!doctype html><body></body>'
})
```

### 验证

- 同 Session 两 WC：仅调用方得到自定义正文
- `getURL()` 为目标站；子资源仍可出网
- 不调用 `protocol.handle`

## 2026-09-11：session.fetch / net.fetch 请求头保序与 headerOrder

### 背景

`session.fetch` 经 `new Request` → 迭代 `Headers` 时，WHATWG **sort-and-combine** 会把自定义头按名字字节序发出，与页面导航（按添加时序）不一致。下游 `ClientRequest` / `net::HttpRequestHeaders` 本身保插入序；问题在 fetch 包装层。

### 修改

1. `lib/browser/api/net-fetch.ts`
   - `headersInOrder(init)`：从 `init.headers`（对象 / 数组）取插入序；若有 `headerOrder` 则按名重排
   - 不再 `for (const [k,v] of req.headers)` 写头
   - 调用方已提供 `sec-fetch-mode` 时，不再自动前置默认 `Sec-Fetch-Mode`
2. `lib/browser/api/session.ts`、`electron.d.ts`、`docs/api/session.md` / `net.md`：类型与文档同步

### 用法

```js
await ses.fetch(url, {
  headers: { /* 任意键序 */ },
  headerOrder: [
    'upgrade-insecure-requests',
    'user-agent',
    'accept',
    'sec-fetch-site',
    'sec-fetch-mode',
    'sec-fetch-user',
    'sec-fetch-dest',
    'accept-language'
  ]
})
```

### 验证

对 [tls.peet.ws/api/all](https://tls.peet.ws/api/all) 对比：`headerOrder` 与故意打乱对象键后的线上自定义头块一致，并可与 `loadURL` 导航自定义头块对齐。`Accept-Encoding` / `priority` 仍可能由栈后补，与导航略有差异（本版不修）。

### 明确不做（本版）

- Chromium 层强制 `priority: u=0` / AE·AL 插位
- `loadURL({ responseOverride })`（另案搁置）

## 2026-08-05：dispatchKeyEvent / dispatchTouchEvent / cancelDragging

### 背景

在已有 `dispatchMouseEvent` 基础上，继续提供免 `debugger.attach` 的 CDP Input 核心自动化能力。

### 修改

| API | 对齐 CDP | 要点 |
|-----|----------|------|
| `dispatchKeyEvent` | `Input.dispatchKeyEvent` | 焦点 widget + `ForwardKeyboardEventWithCommands` |
| `dispatchTouchEvent` | `Input.dispatchTouchEvent` | 维护 touch 会话状态；OOPIF 路由后 TouchEmulator 注入 |
| `cancelDragging` | `Input.cancelDragging` | best-effort：`DragSourceSystemDragEnded` |

既有 `insertText` 已覆盖 CDP `Input.insertText` 的实用场景，未再新增同名路径。

## 2026-08-05：dispatchMouseEvent 补齐 CDP 选配参数

### 背景

初版 `dispatchMouseEvent` 已覆盖点击 / 移动 / 滚轮常用字段，但未接收 CDP 的 `timestamp`、`pointerType` 与触控笔属性。

### 修改

在 `DispatchMouseEvent` 中解析并写入（全部选配，省略行为与原先一致）：

| 字段 | 默认 | 说明 |
|------|------|------|
| `timestamp` | `Now()` | Unix epoch 秒 → TimeTicks |
| `pointerType` | `mouse` | `mouse` \| `pen` |
| `force` | `0` | `[0,1]` |
| `tangentialPressure` | `0` | `[-1,1]` |
| `tiltX` / `tiltY` | `0` | `[-90,90]` |
| `twist` | `0` | `[0,359]` |

对齐 Chromium `InputHandler::CreateWebMouseEvent` 的校验与字段赋值；同步 `electron.d.ts`、API 文档与 spec。

## 2026-07-22：setUserAgent({ hideChrome })（隐藏 window.chrome）

### 背景

站点常通过 `!!window.chrome` 判断 Chromium。Electron 在扩展系统开启时，网页主世界通常仍有空的 `window.chrome`。需要与 UA / platform / Client Hints **同一套** `setUserAgent` 配置面，并支持运行时切换；创建时 `webPreferences` 不够方便。

### 修改

1. **Electron**：`UserAgentOverrideOptions.hideChrome`（默认 `false`）
   - `user_agent_options.{h,cc}`：解析
   - `ElectronBrowserContext`：session 级持久化 + 广播时继承
   - `WebContents::SetUserAgent`：写入 `RendererPreferences.hide_chrome` 并 `SyncRendererPrefs`
   - `electron_render_frame_observer.cc`：主世界保险删除
   - `electron.d.ts` / `docs/api/structures/user-agent-override-options.md`

2. **Chromium 补丁**：`feat_hide_chrome_in_renderer_preferences.patch`
   - `RendererPreferences` / mojom / mojom_traits：`hide_chrome`
   - `NativeExtensionBindingsSystem::UpdateBindingsForContext`：网页上下文若 `hide_chrome`，删除已有 `chrome` 并跳过创建

### 用法

```js
session.defaultSession.setUserAgent(myUA, {
  platform: 'Win32',
  hideChrome: true,
})
```

### 验证

- 未设 / `false`：行为与改前一致
- `true`：主页面 `typeof chrome === 'undefined'`；再次 `hideChrome: false` 可恢复
- 与 `platform` / `userAgentMetadata` 可同传、互不影响

### 明确不做（本版）

- 伪造真 Chrome 的 `chrome.app` / `csi` / `loadTimes`
- `webPreferences.hideChrome`（已弃用该路径）

## 2026-07-21：webContents.dispatchMouseEvent（对齐 CDP Input.dispatchMouseEvent）

### 背景

自动化场景需要与 CDP `Input.dispatchMouseEvent` 相同的真实输入效果（`isTrusted === true`、完整命中测试、OOPIF 路由），但不希望 `webContents.debugger.attach()`。

DOM `element.click()` 是脚本模拟点击（`isTrusted === false`），路径完全不同，不能靠改 DOM API 对齐。

已有 `sendInputEvent` 虽也走 `ForwardMouseEvent`，但参数格式不同于 CDP，且不按坐标异步解析目标 widget（跨域 iframe 场景弱于 CDP）。

### 修改

新增 `webContents.dispatchMouseEvent(params)`：

- 参数与 CDP `Input.dispatchMouseEvent` 对齐：`type` / `x` / `y` / `button` / `clickCount` / `modifiers` / `buttons` / `deltaX` / `deltaY`（`timestamp` / `pointerType` / 笔属性见 2026-08-05 条目）
- 坐标为相对主框视口的 **CSS 像素**，并按 zoom / page scale 换算（同 CDP）
- 通过 `WebContentsImpl::GetRenderWidgetHostAtPointAsynchronously` 路由到正确 RenderWidget（含 OOPIF）
- `Focus()` + `ForwardMouseEvent` / `ForwardWheelEvent`（与 CDP InputInjector 同源管线）
- 返回 `Promise<void>`，**无需** debugger

涉及文件：

- `shell/browser/api/electron_api_web_contents.{h,cc}`
- `docs/api/web-contents.md`
- `electron.d.ts`
- `spec/api-web-contents-spec.ts`

### 用法

```js
await contents.dispatchMouseEvent({
  type: 'mousePressed', x: 100, y: 200, button: 'left', clickCount: 1
})
await contents.dispatchMouseEvent({
  type: 'mouseReleased', x: 100, y: 200, button: 'left', clickCount: 1
})
```

参数名使用 `mouseEvent`（避免与 context-menu 事件的 `params`/`Params` 冲突）。

### 与 debugger / element.click / sendInputEvent 的区别

| | debugger CDP | dispatchMouseEvent | sendInputEvent | element.click() |
|--|-------------|-------------------|----------------|-----------------|
| 需 attach | 是 | 否 | 否 | 否 |
| isTrusted | true | true | true | false |
| OOPIF 坐标路由 | 有 | 有 | 弱（主 widget） | 节点直达 |
| 参数风格 | CDP | CDP | Electron 自有 | DOM |

## 2026-07-21：setUserAgent 实用对齐 CDP Network.setUserAgentOverride

### 背景

CDP 的 `Network.setUserAgentOverride`（实际 redirect 到 `Emulation.setUserAgentOverride`）通过**双通道**生效：

1. Browser：`EmulationHandler::ApplyOverrides` 在请求发出前硬改 `User-Agent` 头  
2. Renderer：`InspectorEmulationAgent::ApplyUserAgentOverride` 覆盖页面侧 UA  

Electron 原有 API 缺口：

| API | 原行为 | 问题 |
|-----|--------|------|
| `session.setUserAgent` | 只写 BrowserContext + NetworkContext | 已有 WebContents 的 RendererPreferences / 子框请求未必更新 |
| `webContents.setUserAgent` | `SetUserAgentOverride(..., false)` | 不标 NavigationEntry；`override_in_new_tabs=false`；子框依赖脆弱路径 |

目标（实用对齐，不含 platform / 完整 Client Hints）：

- 所有相关请求的 `User-Agent` 头一致（含跨域 iframe）
- 顶层与跨域 iframe 的 `navigator.userAgent` 一致（配合既有 OOPIF Chromium 补丁）

> 第二阶段（platform + Sec-CH-\*）见下文「setUserAgent 支持 platform 与 userAgentMetadata」。

### 修改

#### 1. 浏览器侧 URLLoaderThrottle（对齐 CDP ApplyOverrides）

新增：

- `src/electron/shell/browser/net/user_agent_url_loader_throttle.h`
- `src/electron/shell/browser/net/user_agent_url_loader_throttle.cc`

在 `ElectronBrowserClient::CreateURLLoaderThrottles` 中：若 WebContents 存在非空 `GetUserAgentOverride().ua_string_override`，则挂上 throttle，在 `WillStartRequest` / `WillRedirectRequest` 强制写入 `User-Agent` 头。

登记于 `src/electron/filenames.gni`。

#### 2. 强化 `webContents.setUserAgent`

文件：`src/electron/shell/browser/api/electron_api_web_contents.cc`

- 对当前 `NavigationEntry` 调用 `SetIsOverridingUserAgent(!user_agent.empty())`，使渲染发起的导航（含 iframe）经 `ShouldOverrideUserAgentForRendererInitiatedNavigation()` 继承覆盖
- `SetUserAgentOverride(ua, !user_agent.empty())`：非空时 `override_in_new_tabs=true`

#### 3. 强化 `session.setUserAgent`

文件：`src/electron/shell/browser/api/electron_api_session.cc`

- 保留 `NetworkContext::SetUserAgent`（及可选 Accept-Language）
- 遍历 `WebContents::GetWebContentsList()`，对本 session 内所有 WebContents 调用同一套 `SetUserAgent`

#### 4. 测试

- `spec/api-session-spec.ts`：跨域 iframe 请求头断言  
- `spec/api-web-contents-spec.ts`：跨域 iframe 请求头断言  

### 与 Chromium 补丁的关系

`navigator.userAgent` 在 OOPIF 进程仍依赖  
`patches/chromium/fix_allow_ua_override_when_main_frame_is_remote.patch`。  
本次 Electron 改动负责**请求头**与 **NavigationEntry / session 广播**；两者互补构成实用 CDP 对齐。

### 验证

重新编译 Electron 后：

1. `session.setUserAgent('X')` / `webContents.setUserAgent('X')`
2. 顶层与跨域 iframe：`navigator.userAgent === 'X'`
3. 顶层与跨域 iframe 请求：`User-Agent: X`
4. 可跑：`api-session-spec` / `api-web-contents-spec` 中相关用例

## 2026-07-21：setUserAgent 支持 platform 与 userAgentMetadata（Sec-CH-*）

### 背景

CDP `Emulation.setUserAgentOverride` 除 UA 字符串外还可选：

- `platform` → `navigator.platform`
- `userAgentMetadata` → `Sec-CH-UA-*` 请求头与 `navigator.userAgentData`

上一节只对齐了 UA 字符串通道；本阶段补齐这两项。

### 修改

#### 1. Chromium：`RendererPreferences.navigator_platform_override`

补丁：`patches/chromium/feat_navigator_platform_override_in_renderer_preferences.patch`

- mojom / C++ `RendererPreferences` 增加 `navigator_platform_override`
- `WebViewImpl::UpdateRendererPreferences` → `Settings::SetNavigatorPlatformOverride`

#### 2. Electron：解析 CDP 风格 options

新增：

- `shell/browser/user_agent_options.{h,cc}`

`setUserAgent(ua[, options])`：

| 第二参 | 行为 |
|--------|------|
| 省略 | 仅改 UA（metadata 用默认） |
| `string` | 旧 session API：Accept-Language |
| `{ platform, acceptLanguage, userAgentMetadata }` | CDP 风格 |
| `{ userAgentMetadata: null }` | 禁用 `Sec-CH-UA-*`（UA 字符串仍生效） |

`userAgentMetadata` 字段：`brands` / `fullVersionList` / `fullVersion` / `platform` /
`platformVersion` / `architecture` / `model` / `mobile` / `bitness` / `wow64` / `formFactors`。

#### 3. 应用路径

- `webContents.setUserAgent`：写入 `UserAgentOverride.ua_metadata_override` +
  `RendererPreferences.navigator_platform_override`，并 `SyncRendererPrefs`
- `session.setUserAgent`：存入 `ElectronBrowserContext`，更新 NetworkContext，
  广播到同 session 的 WebContents
- 新建 WebContents 从 BrowserContext 继承 platform / metadata

#### 4. 文档与类型

- `docs/api/session.md` / `web-contents.md`
- `docs/api/structures/user-agent-*.md`
- `electron.d.ts`：`UserAgentOverrideOptions` / `UserAgentMetadata`

### 用法

```js
ses.setUserAgent(ua, {
  platform: 'Win32',
  acceptLanguage: 'en-US',
  userAgentMetadata: {
    brands: [{ brand: 'Chromium', version: '120' }],
    platform: 'Windows',
    platformVersion: '15.0.0',
    architecture: 'x86',
    mobile: false,
    bitness: '64'
  }
})
```

注意：`options.platform` 是 `navigator.platform`；`userAgentMetadata.platform` 是
`Sec-CH-UA-Platform`（通常为 `"Windows"` / `"macOS"` 等）。

传 `userAgentMetadata: null` 可去掉 `Sec-CH-UA-*`（对齐 Chromium：有自定义 UA
但不提供 metadata 时禁用 UA Client Hints）。

### 验证

重新编译后：

1. `navigator.platform` 等于 options.platform
2. `navigator.userAgentData.brands` 含自定义 brand
3. 请求中出现对应 `Sec-CH-UA-*`（需站点 Client Hints 协商 / Accept-CH）

## 2026-07-21：跨域 iframe 继承 setUserAgent（Chromium）

### 背景

Electron 中调用 `webContents.setUserAgent()` 后，顶层页面 UA 正确，但**跨域 iframe** 仍使用默认 UA。

跨域 iframe 通常作为 OOPIF 运行在独立渲染进程。该进程内 `WebView::MainFrame()` 是 `WebRemoteFrame` 代理，没有本地 `WebDocumentLoader`，无法读取 `DocumentState::is_overriding_user_agent()`。

### 修改

**文件：** `src/content/renderer/render_frame_impl.cc`  
**函数：** `RenderFrameImpl::ShouldUseUserAgentOverride()`

```cpp
if (web_view->MainFrame()->IsWebRemoteFrame())
  return true;  // 原为 return false
```

**Electron 补丁：**

- 路径：`src/electron/patches/chromium/fix_allow_ua_override_when_main_frame_is_remote.patch`
- 已登记于：`src/electron/patches/chromium/.patches`

### 原理

1. `webContents.setUserAgent()` → `WebContents::SetUserAgentOverride()`，将自定义 UA 写入 `RendererPreferences.user_agent_override`，并经 `SyncRendererPrefs()` 同步到各渲染进程。
2. Blink 通过 `UserAgentOverride()` / `UserAgentMetadataOverride()` 取覆盖值，二者均受 `ShouldUseUserAgentOverride()` 门控。
3. 原逻辑在「主框为 remote」时直接返回 `false`（临时规避 [crbug.com/426555](https://crbug.com/426555)），导致 OOPIF 进程忽略已同步的自定义 UA。
4. 改为 `return true` 后，该场景直接使用 `RendererPreferences` 中的 UA 覆盖，跨域 iframe 即可继承。

同进程本地主框路径不变：仍按 `document_state->is_overriding_user_agent()` 判断。

### 关联问题

- [electron#40374](https://github.com/electron/electron/issues/40374) — session.setUserAgent 不被 iframe 继承
- [electron#40990](https://github.com/electron/electron/issues/40990) — iframe 不能继承 webContents 修改的 UA
- [crbug.com/426555](https://crbug.com/426555) — remote 主框缺少 DocumentLoader 的上游 TODO

### 验证

重新编译后，在已 `setUserAgent` 的页面加载跨域 iframe，检查：

1. iframe 内 `navigator.userAgent`
2. iframe 发出请求的 `User-Agent` 头

均应为自定义 UA。
